一台归一化的数字功率计
——从 ADC 码值到示波器读数的完整账本

这个工程只做一件事：把 PA1 上的电压每 20.83 µs 采一个点，算出这个点偏离 1.65 V 多少， 平方，然后同时用三种不同方式平均。所有数字都是以 1.65 V 为基准的归一化值， 不是伏特也不是瓦特。这份手册把"理论应该是多少、实际会是多少、为什么不一样、 在哪三个地方能读到它、这四处读数怎么互相换算"全部摊开写清楚。

i

先看这一条，能省掉你两个小时的抓狂： 波形发生器接 PA1 之前，必须把输出直流偏置设到 1.65 V。 发生器默认输出是绕 0 V 摆的，2 Vpp 就是 −1 V ~ +1 V，直接怼到 STM32 的模拟输入上： 负半周会被芯片内部的 ESD 保护二极管钳到约 −0.3 V（绝对最大额定 VSS−0.3 V， 余量只有 0.3 V，有损伤引脚的风险），而且算出来的功率会飞到理论值的 近 4 倍（实测 +285%，见 第 7 节）。

1这是什么

一句话：PA1 进、三种功率估计、两个出口。

一根模拟输入线，两个输出口：

  • 模拟表盘 —— PA4 输出一个和 RMS 成正比的直流电压。 万用表或示波器直接量，读数 ÷ 2 就是输入信号的 Vrms。不开电脑也能读数。
  • 数字表盘 —— PA2 每约 10.7 ms 发一行 7 列 CSV 给 PC， 上位机实时画 5 条曲线，并能导出。

这两个出口说的是同一件事的两种表示。第 6 节 有一张"三处读数对账表"，专门解决"示波器上读到的和电脑上看到的是不是一回事"。

!

加偏置的三种做法，按推荐顺序：

① 发生器直接设 DC 偏置 1.65 V（最省事）
大多数函数发生器有 Offset 或 DC Offset 旋钮/菜单。 设 1.65 V，幅度 1 V（即 2 Vpp）。示波器量一下输出确实是 0.65 V ~ 2.65 V 再接到板子上。

② 1.65 V 直流源 + 串联隔直电容
需要两个电阻分压出 1.65 V（比如 3.3 V 经两个等值电阻），再串一个 1~10 µF 电容把交流叠上去。 优点是不需要发生器有偏置功能；缺点是加电/断电瞬间电容充放电会产生冲击， 务必先接好再上电。

③ 只用发生器、不加偏置 —— 不要这么做。 见第 7 节的实测数字。

!

偏置不是"差不多就行"。代码里 2048 码值硬编码为"零"， 而 2048 码值对应的真实电压是 VDDA/2。偏 49 mV 就吃掉 0.54% 精度， 偏 149 mV 就吃掉 4.5%，偏 250 mV 就吃掉 12.5%。 如果你是用电阻分压凑的 1.65 V，先拿万用表量准了再上板。

顺便：DISC1 用 USB 供电时 VDDA 实测常在 3.28~3.35 V 飘， 这会让"1.65 V"这个基准本身有一点偏差 —— 属于全局乘性误差，无法在固件里消除， 只能实测后在校准里补偿。

数据线两种接法，代码完全一样

A. 板载 ST-LINK 虚拟串口（推荐）

一根 USB 线插开发板即可。PA2/PA3 在板内已连到 ST-LINK， PC 上出现 STMicroelectronics Virtual COM Port (COMx)。

B. 外接 CH340

PA2(TX) → CH340 RXD，PA3(RX) → CH340 TXD，GND ↔ GND。 PC 上出现 USB-SERIAL CH340 (COMx)。

串口列表里如果看到"蓝牙链接上的标准串行"，那不是板子，别选错。

关键的三步换算，必须记住

// 第 ① 步：把码值变成"偏离中点的比例"
x = (码值 − 2048) / 2048    = (V − 1.65) / 1.65，范围 −1 ~ +1
// 第 ② 步：功率就是 x 的平方（归一化）
p = x²    // 物理功率 = p × 1.65² = p × 2.7225 [V²]
// 第 ③ 步：三种平均 → RMS → 两个出口
RMSwin = √(mean(p))     // 归一化 0~1
输入 Vrms = RMSwin × 1.65 V     // ← 上位机"输入 Vrms"那一格
PA4 电压 = RMSwin × 3.3 V   = 2 × 输入 Vrms    // ← 示波器读到的
✓

"为什么 PA4 是输入 Vrms 的两倍？" 因为归一化把 1.65 V 压成了 1.0，而 DAC 的满量程是 3.3 V。 两者之比正好是 2，于是 3.3 V 的 DAC 输出恰好等于 2 × Vrms。

这不是巧合，也不是设计失误 —— 它的好处是满幅方波正好顶到 DAC 满量程， 一点量程都不浪费。代价是你必须记住"看到 1.414 V 其实是 0.707 Vrms"。

!

全部数字都是归一化的，这一条最容易翻车。 CSV 里的 Pwin = 0.183655 不是 0.18 瓦特，是"以 1.65 V 为基准的相对功率"。 想变成物理量：

物理功率 P = Pwin × 1.65² = Pwin × 2.7225  [V²]
若负载 1 Ω，数值上就等于瓦特（0.183655 × 2.7225 = 0.5000 W）

物理能量 = E × 1.65² / 48000  [V²·s]

5示波器上看到的是什么

一根直流线，但它的"平不平"藏着信息。

第一件事：必须切 DC 耦合

!

PA4 输出的是纯直流。示波器如果停在 AC 耦合， 直流成分会被高通滤掉，屏幕上只剩噪声和纹波，读数接近 0 —— 然后你会开始怀疑板子坏了、固件没跑、DAC 没使能。

先把耦合切到 DC。探针接 PA4，地夹接 GND。

第二件事：它应该是一条水平线

1 kHz / 2 Vpp 输入
1.414V
1 kHz / 1 Vpp 输入
0.707V
100 Hz / 2 Vpp 输入
1.414V± 8%
50 Hz / 2 Vpp 输入
1.414V± 6%

第三件事：这条线的"纹波"由输入频率决定

这不是故障，是滑动窗口的物理必然。窗口固定 1024 点 = 21.33 ms， 如果输入信号的周期比窗口还长（低频），窗口里装不满一个完整周期，平均值就会跟着相位起伏。

而真正起作用的是 x² 的频率（2f），不是 f 本身 —— 正弦平方会把它变成两倍频率再加一个直流分量：

数字来自把固件算法原样搬到 numpy 里跑的仿真（含 12 位量化、开机填充、 α 逐点递推），不是估算。E

i

为什么 1 kHz 的纹波只有 1.3%，而 2 kHz 分量应该被压得更狠？ 滑动平均对频率 f 的增益是 |sin(πfT)/(πfT)|。窗口 T = 21.33 ms：

· f = 2 kHz（1 kHz 信号产生）→ πfT = 134 rad → 增益 0.65%
· f = 100 Hz（50 Hz 信号产生）→ πfT = 6.7 rad → 增益 6%

所以 50 Hz 的纹波是 1 kHz 的九倍。这条正好能拿去答教材 A1、A2。

第四件事：还有一个 94 Hz 的台阶

PA4 每 10.67 ms 才更新一次（跟着串口上报节奏），把示波器时基调到 1 ms/div 细看，能看到阶梯状逼近。稳态时台阶可忽略，但你在改信号幅度时， 会看到一条约 94 Hz 的阶梯曲线在逼近新值 —— 这是正常的。

!

"没信号时 PA4 是不是 0 V？"理论上是，实际不是。 12 位量化的 LSB 是 3.3/4096 = 0.806 mV，量化噪声约 0.233 mVrms； 再叠加参考电压抖动和输入端拾取的噪声，实测 PA4 会停在 几毫伏到几十毫伏。如果你输入端有 5 mVrms 的噪声，PA4 就停在大约 10 mV。

I 具体数值取决于你的信号源和板子噪声， 方向一定对，量级参考上面的仿真。

!

DAC 输出缓冲的两端有约 0.2 V 的不可达区。 带输出缓冲时，PA4 实际能到的范围大约是 0.2 V ~ (VDDA − 0.2 V)， 不是精确的 0 ~ 3.3 V。所以：

· 满幅方波时 PA4 顶不到 3.3 V，会在 3.1 V 附近饱和；
· 无信号时也下不到 0 V。

因此"PA4 = 2 × Vrms" 这个关系在两端 10% 的范围内会失真。 做精度实验请把工作点放在中间区域（0.5 ~ 2.5 V）。

I 具体不可达区的数值请查你那颗芯片的 datasheet 的 DAC 特性表，并用万用表实测确认 —— 我这里只能告诉你"有这个现象、方向如此"。

Pexp 在低频时摆得厉害，不是坏了。 α = 0.99 的时间常数只有 2.07 ms，比 50 Hz 的周期（20 ms）短得多 —— 它"跟得太快"，于是把 x² 的 100 Hz 起伏原原本本跟出来了。50 Hz 输入时纹波高达 122%， 橙线会在 0 和 0.37 之间来回跳。要看稳态值请读 Pwin。

教材 A4 问"α 趋近 1 会怎样" —— 答案就在这个反直觉的地方：α 越大越平滑， 但 τ 越小？不对。τ = −1/(ln α)/fs，α 越接近 1，分母越小，τ 越大， 越平滑越慢。α=0.99 时 τ=2.07 ms；α=0.999 时 τ=20.7 ms，就会明显更平滑也更迟钝。

同一个信号，你会从三个地方读到数。它们必须互相自洽，否则就是有地方错了。

对账的三条铁律

① 示波器 PA4 读数 ÷ 2 = 上位机"输入 Vrms"。 如果不等，先查示波器是不是 AC 耦合，再查是不是探头衰减比设错了（10X 探头但示波器认为 1X， 读数会小十倍）。

② 上位机"输入 Vrms"× √2 × 2 = 输入信号的峰峰值。 0.707 × 1.414 × 2 = 2.000 Vpp ✓。用它反过来验证发生器设得对不对。

③ 用示波器直接量 PA1 的峰峰值，比发生器面板可信得多。 很多发生器带 50 Ω 输出阻抗，接上负载（哪怕只是探头）电压就会掉几个百分点； 还有的不带负载时读数是开路值。教材 A5 问"为什么 MATLAB 和硬件结果可能不同" —— 发生器面板值不等于实际输出，就是最常被忽略的一条。

✓

一个自洽性检查（建议每次实验都做）： 在 1 kHz / 2 Vpp 下，把上位机这三格抄下来：

Pwin = 0.183655  ·  RMSwin = 0.428550  ·  输入 Vrms = 0.7071 V
三者必须满足 Pwin = (RMSwin)² 且 RMSwin = Vrms / 1.65
误差超过 1% 说明：偏置不准 / 发生器实际输出不是 2 Vpp / VDDA 明显偏离 3.3 V

为什么直流偏置的误差是"平方级"的？

设真实信号是 v = d + a·sin(ωt)，其中 d 是偏置误差。那么

x = (d + a·sin) / 1.65
x² = (d² + 2ad·sin + a²·sin²) / 1.65²
// 对一个完整周期取平均，sin 项归零，sin² 项 → 1/2
mean(x²) = (d² + a²/2) / 1.65²

看到那个 d² 了吗？直流分量不论正负，都会变成正能量加进去。 这是不可逆的 —— 你无法在后期从结果里把 d² 减掉，因为不知道 d 是多少（除非另外量）。

所以：偏置必须用示波器或万用表量准，不能靠"看起来差不多"。

i

还有两个无法消除的系统误差：

① VDDA 不等于 3.3 V。代码把 2048 码值当 1.65 V， 但真实关系是 2048 码值 = VDDA/2。DISC1 用 USB 供电时实测 3.28~3.35 V 飘， 于是"1.65"这个基准本身有 ±1% 的偏差，直接变成全局乘性误差。

② ADC 的积分非线性（INL/DNL）。F407 的 12 位 ADC 典型 INL ±2 LSB， 折算到 Pwin 是 0.1% 量级。

I 这两条的数值来自器件手册的典型值， 没有在你的板子上实测。想验证第一条：用万用表量 VDDA 引脚（PA1 附近有测试点）。

9采样率实验的三个坑

教材第 11 节让你测 24 / 48 / 96 kHz。改一个宏就行，但下面三件事会让你得出错误结论。

好消息：本工程把采样率做成了宏，改 SAMPLE_FS_HZ 一个数， TIM2 的 ARR 会自动跟着算，三个目标值都能整除：

24 kHz → ARR = 84e6/24000 − 1 = 3499  ·  48 kHz → 1749  ·  96 kHz → 874

坑 ①：窗口的"点数"不变，但"时长"变了

SAMPLE_WIN_M 固定 1024 点，SAMPLE_ALPHA 固定 0.99 —— 所以改采样率时，滤波器的时间尺度也跟着变了：

看到最后两列了吗？采样率越高，纹波越大 —— 但这不是"采样率高精度差"， 而是你把窗口缩短了 4 倍。

如果照着这个工程直接做教材 A2（"RMS 精度如何随采样率变化"）， 你会得出一个错误结论。正确做法有两种，二选一，报告里必须说清楚你选了哪个：

做法 A（推荐）：保持窗口时长不变。 改 SAMPLE_FS_HZ 时同步改 SAMPLE_WIN_M， 让 WIN_M / FS 恒等于 21.33 ms：
24 kHz → SAMPLE_WIN_M = 512；48 kHz → 1024；96 kHz → 2048。
α 也要同步：保持 τ = 2.07 ms → 24 kHz 用 0.995，48 kHz 用 0.99，96 kHz 用 0.9786。

做法 B：承认窗口变短。 报告里明确写"本实验固定窗口点数，因此滤波器时间常数随采样率同比变化"， 然后把纹波变化归因于窗口变短，而不是采样率本身。

坑 ②：96 kHz 时串口一定丢行

115200 8N1 的可用带宽是 11520 字节/秒（每位 1 个 bit，每字节 10 bit）。 每块 DMA 数据 256 点，块时长 = 256 / 采样率。行宽实测 64~72 字节（E 涨到 8 位数后变长）。

占用率 117% 不是"稍微丢一点"，是稳定地每两行丢一行。 丢行由 Usart_SendLine 主动丢弃（上一包没发完就返回 0）， 不阻塞主循环 —— 所以采样照常，只是上位机少几行。上位机状态栏会显示"丢 N 行"。

坑 ③：上位机的采样率参数必须同步改

上位机横轴是 N / fs。固件改成 96 kHz 而上位机还留 48000， 横轴时间会变成真实时间的一半，你会看着一条被横向拉长的曲线纳闷。 改完固件记得在参数行把"采样率"也改掉，按回车生效。

正确的实验步骤

  1. 改 SAMPLE_FS_HZ（必须）
  2. 改 SAMPLE_TX_BLOCKS：24 kHz 用 1，48 kHz 用 2，96 kHz 用 4
  3. 按"做法 A"决定要不要同步改 SAMPLE_WIN_M 和 SAMPLE_ALPHA
  4. 编译 → F8 下载
  5. 上位机参数行改采样率，按回车
  6. 记录 Pwin / RMSwin / 输入 Vrms，以及你选的窗口配置

注意 ADC 采样时间 84 个 ADC 时钟 = 4.0 µs。 96 kHz 时触发周期只有 10.4 µs，"采样+转换"（84+12 周期 = 4.57 µs）占 44% —— 仍然可行，但没有更多余量了。如果要上 192 kHz，得先把这个值降下来。

10奈奎斯特：一个反直觉的结论

教材 A1 问"输入频率接近奈奎斯特极限时会发生什么"。多数人会答错。

直觉答案："超过 Nyquist 就混叠了，RMS 会算错。" —— 对单频正弦，这是错的。 我把频率从 10 kHz 扫到 20 kHz（24 kHz 采样，Nyquist 是 12 kHz）实测了一遍：

采样率输入频率相对 Nyquist 实测 Pwin误差现象
24 kHz10 kHz83% 0.18369+0.02%正常
24 kHz11 kHz92% 0.18369+0.02%正常
24 kHz12 kHz 100%0.00000 −100% 采样点全落在过零点 → 全部读到 2048 → x≡0
24 kHz13 kHz108% 0.18369+0.02% 已经混叠，但功率对
24 kHz20 kHz167% 0.18368+0.01% 严重混叠，功率依然对
48 kHz24 kHz100% 0.00000−100%同上，同样归零
✓

正确结论（可以照着答 A1/A2）：

对单频正弦，RMS 是一个二阶统计量（方差）， 而混叠只改变频率的归属、不改变总功率。 这就是帕塞瓦尔定理的直接体现：时域能量 = 频域能量，采样只是重新分配了频谱的位置。

所以 RMS 测量对采样率极不敏感（上面全是 ±0.02%）。 采样率真正影响的是波形形状的保真度和宽带信号的正确归属， 不是单频信号的功率。

唯一的例外是恰好 f = fs/2 这个退化点： 采样点如果正好全落在过零点（相位锁定），会读到全是 2048，Pwin 归零。 这是"采样与信号同步"的极端情况，实际会看到读数在 0 和正常值之间跳。

!

那什么时候采样率真的会影响 RMS 精度？

① 信号不是单频（方波、三角波、含谐波、含噪声）→ 高次谐波被折返，会改变功率分布；
② 抗混叠滤波器缺失 → F407 的 ADC 前端没有抗混叠滤波，超过 Nyquist 的噪声会折返进基带， 让读数偏高（这部分是真实的额外功率，不是误差）；
③ 窗口时长变了（见第 9 节坑 ①）→ 纹波变化会让"单次读数"偏离稳态值。

所以 A2 的完整答案应该是："对纯正弦、稳态测量，RMS 精度几乎不随采样率变化； 但采样率会改变滤波器时间常数、影响宽带信号的正确性、并决定能否分辨波形。"

A附录：公式推导

为什么 mean(sin²) = 1/2

sin²θ = (1 − cos 2θ) / 2
// cos 2θ 在一个完整周期内积分为 0
mean(sin²) = 1/2

正弦的归一化功率

设 v = 1.65 + A·sin(ωt)
x = (v − 1.65)/1.65 = (A/1.65)·sin(ωt)
// 记 a = A/1.65（归一化幅度）
p = x² = a²·sin²(ωt)
mean(p) = a²/2 = (A/1.65)²/2  ✓ 与第 4 节一致

滑动平均的频率响应（用来算纹波）

H(f) = |sin(πfT) / (πfT)|    T = 窗口时长

// 48 kHz、WIN=1024 → T = 21.33 ms
f = 100 Hz（50 Hz 信号产生）→ πfT = 6.70 → H = 6.0%
f = 2 kHz（1 kHz 信号产生）→ πfT = 134  → H = 0.65%

指数平均的时间常数

y[n] = α·y[n−1] + (1−α)·x[n]
// 等价于连续域的一阶低通，τ = 1/(1−α) 个采样点
τ = 1 / ((1−α)·fs)    α=0.99, fs=48k → τ = 2.083 ms（严格式 −1/(ln α·fs) = 2.074 ms）

能量与功率的关系

E(n) = Σk=0..n x²[k]    // 离散求和，无时间单位
Pall = E(n) / n    // 时域平均 = Pwin 的极限

// 换成物理能量要乘采样间隔
E物理 = E × 1.65² / fs  [V²·s]

G 猜测 —— 纯为观感手调，没有数据支撑。 本手册没有 G 级数据。所有数值要么是公式推的，要么是仿真量的， 要么是从编译产物读的。
