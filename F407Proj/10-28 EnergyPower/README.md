# STM32F407 · 实时功率/能量测量（ADC + DMA + 串口上传）

基于 **Keil MDK-ARM + ST 标准外设库（StdPeriph V1.9.0）** 的 DSP 功率测量工程，
板子为 **STM32F407G-DISC1**。

功能一句话：**PA1 以 48 kHz 采样，每个点算瞬时功率 x²，同时维护三种功率估计
（累积能量 / 滑动窗口 / 指数平均），PA4 输出一个正比于 RMS 的直流电压，
PA2 每秒约 94 行 CSV 发给 PC；附带一个 Python 上位机实时画曲线。**

> 本工程是 DSP 实验 `DSP_EnergyPower` 的独立重写版。
> 原版用 CubeIDE + HAL + **USB CDC 设备**；这一版换成 Keil + 标准库 + **USART2**
> （板载 ST-LINK 虚拟串口或外接 CH340），PC 端同样是一个 COM 口，
> 功能完全等价，但省掉了在标准库工程里搬 HAL PCD 驱动的麻烦。
>
> 相比原版改了三处：**ADC 采样时间 3 → 84 个周期**（精度）、
> **采样率做成宏**、**DAC 更新跟着上报节奏**（不再每圈狂写）。

## 一、这个项目做什么

### 数据流

```
PA1 (0~3.3 V，必须围绕 1.65 V 摆动)
     │  TIM2 每 20.83 µs 触发一次（48 kHz）
     ▼
ADC1 12 位 ──DMA2_Stream0 循环搬运──► Sample_Buf[512]（乒乓）
     │                                     │
     │                    半满(256点)/全满(256点)各触发一次中断
     │                                     ▼
     │                    x = (码值 − 2048) / 2048   →   p = x²
     │                                     │
     │        ┌────────────────┬───────────┴──────────┐
     │        ▼                ▼                      ▼
     │    累积能量          滑动窗口               指数平均
     │    E += x²          Pwin (1024点)          Pexp (α=0.99)
     │                        │                      │
     │                        └──────┬───────────────┘
     ▼                               ▼
  PA4 (DAC1) ◄── RMS × 3.3V     USART2 ──► PC（CSV）
  = 输入 Vrms × 2
```

### 三种估计器的区别（这是本课的核心）

| 估计量 | 公式 | 时间尺度 | 特点 |
|---|---|---|---|
| `E` 累积能量 | `Σ x²` | 从开机至今 | 单调增长，反映总能量，看不出当前强弱 |
| `Pwin` 滑动窗口 | `(1/1024)·Σ最近1024点 x²` | 窗口 **21.33 ms** | 平滑准确，但滞后半个窗口 |
| `Pexp` 指数平均 | `0.99·Pexp + 0.01·x²` | τ ≈ **2.08 ms** | 响应快，纹波大 |
| `Pall` 总平均 | `E / N` | 全部历史 | 开机越久越稳 |

同一个信号，三条曲线会明显不一样 —— 上位机的图上一眼就能看出来。

## 二、硬件与接线

| 引脚 | 干什么 | 说明 |
|---|---|---|
| **PA1** | 模拟输入（ADC1_IN1） | 0~3.3 V，**必须围绕 1.65 V 摆动**（代码把 2048 当零点） |
| **PA4** | DAC1_OUT1 模拟输出 | 直流，0~3.3 V，= 输入 Vrms × 2 |
| **PA2** | USART2_TX | 接 PC（见下面两种接法） |
| **PA3** | USART2_RX | 本工程没用到，接着也无妨 |
| **GND** | 地 | 必须共地 |

### 数据线两种接法，代码完全一样

**A. 板载 ST-LINK 虚拟串口**（推荐，最省事）
一根 USB 线插开发板的 USB 口即可，PA2/PA3 板内已经连到 ST-LINK 了，
PC 上会出现 `STMicroelectronics Virtual COM Port (COMx)`。

**B. 外接 CH340 模块**

```
F407 PA2 (TX) → CH340 RXD
F407 PA3 (RX) → CH340 TXD      （本工程不发数据给板子，这条可省）
F407 GND      → CH340 GND      ← 一定要接
```

PC 上出现 `USB-SERIAL CH340 (COMx)`。

## 四、CSV 格式与单位换算

板子每秒发约 94 行，7 列，逗号分隔，`\r\n` 结尾：

```
N,E,Pwin,Pexp,Pall,RMSwin,RMSexp
1234567,12.345678,0.500000,0.498000,0.499000,0.707107,0.705700
```

| 列 | 含义 | 单位 | 换算成物理量 |
|---|---|---|---|
| `N` | 累计采样点数 | 点 | `N / 48000` = 开机秒数 |
| `E` | 累积能量 Σx² | 归一化 | × 1.65² ÷ 48000 = V²·s |
| `Pwin` | 滑动窗口平均功率 | 归一化 | × 1.65² = V²（1 Ω 负载下即 W） |
| `Pexp` | 指数平均功率 | 归一化 | 同上 |
| `Pall` | 总平均功率 | 归一化 | 同上 |
| `RMSwin` | 滑动窗口 RMS | 归一化 0~1 | **× 1.65 V = 输入 Vrms** |
| `RMSexp` | 指数平均 RMS | 归一化 0~1 | 同上 |

**全是归一化值，不是伏特也不是瓦特**，这一点一定要清楚。

### PA4 的电压和输入 RMS 是 2 倍关系

```
DAC 输出电压 = 归一化 RMS × 3.3 V = (输入 Vrms / 1.65) × 3.3 = 输入 Vrms × 2
```

| 输入（围绕 1.65 V） | RMSwin | PA4 输出电压 | 万用表读数 |
|---|---|---|---|
| 满幅正弦（峰峰 3.3 V） | 0.707 | 2.33 V | 2.33 V |
| 满幅方波（0↔3.3 V） | 1.000 | 3.30 V | 3.30 V |
| 半幅正弦（峰峰 1.65 V） | 0.354 | 1.17 V | 1.17 V |
| 无信号（恒定 1.65 V） | 0 | 0 V | 0 V |

## 六、关键参数怎么改

全部在 **`Hardware\Sample.h`** 顶部：

```c
#define SAMPLE_FS_HZ        48000U    /* ★ 采样率，改这一个数就行 ★ */
#define SAMPLE_TIM_ARR      ((84000000U / SAMPLE_FS_HZ) - 1U)   /* 自动算 */

#define SAMPLE_BUF_LEN      512U      /* DMA 缓冲总点数，必须能被 2 整除 */
#define SAMPLE_WIN_M        1024U     /* 滑动窗口点数 */
#define SAMPLE_ALPHA        0.99f     /* 指数平均系数 */
#define SAMPLE_TX_BLOCKS    2U        /* 每几块发一行 CSV */
```

### 改采样率

| `SAMPLE_FS_HZ` | ARR | 每块时长 | 备注 |
|---|---|---|---|
| 8000 | 10499 | 32 ms | 省 CPU，但 Nyquist 只有 4 kHz |
| 16000 | 5249 | 16 ms | 通用 |
| **48000**（默认） | 1749 | 5.33 ms | 音频标准 |
| 96000 | 874 | 2.67 ms | 要确认 84e6/96000 = 875 整除 |

### 改估计器响应速度

- **滑动窗口**：改 `SAMPLE_WIN_M`。窗口越长越平滑越滞后。
  注意窗口必须远大于信号周期，否则平均值会跟着信号相位起伏
  （50 Hz 在 21.33 ms 窗口里只有 1.07 个周期，就是这么来的）。
- **指数平均**：改 `SAMPLE_ALPHA`。越接近 1 越平滑，τ = 1/(1-α)/fs。

### 改上报频率

`SAMPLE_TX_BLOCKS` 是"每几块 DMA 数据发一行"。每块 5.33 ms：
- 2（默认）→ 10.67 ms 一行 ≈ 94 Hz
- 1 → 5.33 ms 一行 ≈ 188 Hz，但 115200 波特率下带宽不够（会丢行）
- 4 → 21.3 ms 一行 ≈ 47 Hz，适合更低波特率

### 改串口

`Hardware\Usart.h` 里的 `USART_BAUD_HZ`（默认 115200）。

## 八、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 上位机收不到数据 | ① 选错串口（别选蓝牙口）；② 串口助手还占着口；③ 线只是充电线；④ 检查 PA2 有没有接对 |
| 数据能收但 N 不涨 | 采样没跑起来：检查 TIM2 是否使能、DMA 是否在循环模式 |
| N 涨到 512 就停 | DMA 没进循环模式：确认 `ADC_DMARequestAfterLastTransferCmd(ADC1, ENABLE)` 和 `DMA_Mode_Circular` 都设了 |
| Pwin 一直是 0 | PA1 没有信号，或者信号是恒定直流（x 恒为 0） |
| PA4 电压对不上 | 换算关系是 `输入 Vrms × 2`，不是直接读 Vrms，见第四节 |
| PA4 一直是 0 | `Dac_SetRms()` 没被调用，或者 RMS 真的是 0 |
| 数值全都在 0 附近但噪声很大 | 输入信号没围绕 1.65 V 摆动，先量一下 PA1 的直流电平 |
| 上位机卡顿 | 把 `PLOT_INTERVAL_MS` 调大（默认 200 ms），或者减少显示曲线 |
| 丢行很多 | 波特率不够：提高 `USART_BAUD_HZ`（CH340 可到 460800）或加大 `SAMPLE_TX_BLOCKS` |

### 几处"非原生"的处理（别踩回去）

1. **CMSIS 用 5.6.0 而不是 4.00**：4.00 的 `core_cmFunc.h` 里 `VMSR fpscr` 那行在
   armclang 下报错。也**不要**换 CMSIS 6.x（`NVIC->IP` 改名成 `IPR`，标准库编译不过）。
2. **编译器固定 AC6**，汇编器仍用 `armasm`。
3. **`stm32f4xx_fmc.c` 不参与编译**：FMC 是 F429/F439 的外设。
4. **加了 `-Wno-macro-redefined`**：压掉标准库自己的宏重复定义警告。

### 晶振不是 8 MHz 时（两处必须一起改）

| 改哪里 | 改什么 | 本板（DISC1，8 MHz）的值 |
|---|---|---|
| `User\system_stm32f4xx.c` | `PLL_M` | `8` |
| Keil `Options → C/C++ → Define` | `HSE_VALUE` | `8000000` |

只改一处会让主频跑偏 —— 本工程的 48 kHz 依赖 84 MHz 定时器时钟，**时钟错了采样率就跟着错**。
